# ภาพรวมระบบ: เว็บแอปคำนวณคาร์บอนฟุตพรินต์องค์กร + จำลองโครงการ T-VER + ประเมินการยกเว้นภาษี

> เอกสารนี้สรุปจากซอร์สโค้ดใน repo `carbon-project` (โปรเจกต์จบของมหาวิทยาลัย) ณ วันที่ 20 พ.ย. 2569 (2026-11-20)
> ใช้เพื่อให้ผู้อ่าน (คนหรือ AI) เข้าใจว่าระบบทำอะไรได้บ้าง ข้อมูลมาจากไหน และผลลัพธ์คืออะไร
> หน่วย: kgCO2e = กิโลกรัมคาร์บอนไดออกไซด์เทียบเท่า, tCO2e = ตันคาร์บอนไดออกไซด์เทียบเท่า (1 tCO2e = 1,000 kgCO2e)

---

## 1. ระบบนี้คืออะไร

เว็บแอปสำหรับ **องค์กร (บริษัท)** ในประเทศไทย ใช้สำหรับ

1. **บันทึกและคำนวณคาร์บอนฟุตพรินต์ขององค์กร (CFO)** แยกตาม Scope 1 / 2 / 3 จากข้อมูลกิจกรรม เช่น ไฟฟ้า น้ำประปา น้ำมัน โดยมี OCR ช่วยอ่านบิลมากรอกให้อัตโนมัติ
2. **แนะนำแนวทางลดคาร์บอน** ตามเงื่อนไขที่ผู้ดูแลระบบตั้งไว้ พร้อมประมาณว่าลดได้กี่ tCO2e
3. **คำนวณกิจกรรมทั่วไป** (การประชุม/อบรม/อีเวนต์ และการเดินทาง) พร้อมคำแนะนำ และดาวน์โหลดผลเป็น PDF
4. **จำลองโครงการปลูกป่าตามมาตรฐาน T-VER** (โครงการลดก๊าซเรือนกระจกภาคสมัครใจของ อบก.) เพื่อคำนวณคาร์บอนเครดิตที่จะได้
5. **จัดสรรคาร์บอนเครดิต** ว่าจะเอาไปชดเชยการปล่อยของตัวเองเท่าไร และนำไปขายเท่าไร
6. **ประเมินภาษีเงินได้นิติบุคคลที่ได้รับยกเว้น** จากรายได้การขายคาร์บอนเครดิต
7. **ดาวน์โหลดเอกสาร** ที่ผู้ดูแลระบบอัปโหลดไว้

ผู้ใช้มี 2 บทบาท (เก็บในคอลัมน์ `role` ของตาราง `user`)
- **organization** = ผู้ใช้ฝั่งองค์กร ใช้งานฟีเจอร์ข้างบน เห็นเฉพาะข้อมูลขององค์กรตัวเอง
- **admin** = ผู้ดูแลระบบ ตั้งค่าข้อมูลอ้างอิงทั้งหมด (EF, GWP, รายการกิจกรรม, แนวทางลดคาร์บอน, เงื่อนไข T-VER, เป้าหมายการจัดสรร, ต้นทุนมาตรฐาน, เอกสาร)

## 2. เทคโนโลยีที่ใช้

| ส่วน | เทคโนโลยี |
|---|---|
| หน้าเว็บ + API | Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4 |
| ฐานข้อมูล / ล็อกอิน / ไฟล์ | Supabase (PostgreSQL + Supabase Auth + Storage) ใช้ Row Level Security (RLS) แยกข้อมูลแต่ละองค์กร |
| OCR อ่านบิล | Python FastAPI (`scripts/api.py`) + PaddleOCR + โค้ดดึงข้อมูลจากบิล (`scripts/extract_bill_data.py`) |
| สร้าง PDF | `@react-pdf/renderer` (ฝั่ง server) และ `html2pdf.js` / `jspdf` (ฝั่ง browser) |
| อื่นๆ | `sharp`, `unpdf`, `tesseract.js` (ใช้ทดลอง), Dockerfile สำหรับ deploy |

โครงสร้างโฟลเดอร์หลัก
- `src/app/organization/...` หน้าฝั่งองค์กร
- `src/app/admin/...` หน้าฝั่งผู้ดูแลระบบ
- `src/app/api/...` API (ล็อกอิน ลงทะเบียน บัญชี OCR)
- `src/lib/...` ฟังก์ชันกลาง (สูตร T-VER, แนวทางลดคาร์บอน, ตรวจข้อมูล, ตรวจ SQL Injection, OCR บิล)
- `supabase/*.sql` สคริปต์ฐานข้อมูล (RLS, trigger, ปรับโครงสร้าง) ต้องรันเองใน Supabase SQL Editor
- `scripts/*.py` เซิร์ฟเวอร์ OCR (Python)

## 3. ข้อมูลมาจากไหน

ข้อมูลในระบบมี 3 แหล่ง

### 3.1 ข้อมูลอ้างอิงที่ผู้ดูแลระบบกรอก (ค่ากลางทุกองค์กรใช้ร่วมกัน)
| ตาราง | เนื้อหา | หน้าแอดมิน |
|---|---|---|
| `carbon_scope` | Scope 1/2/3 (หมายเลข + ชื่อขอบเขต) | `/admin/activities` |
| `activity` | กิจกรรมในแต่ละ Scope เช่น "การใช้ไฟฟ้า" | `/admin/activities` |
| `activity_detail` | รายการย่อยที่องค์กรต้องกรอก เช่น "ไฟฟ้าจากการไฟฟ้า (kWh)" ผูกกับค่า EF, GWP, หน่วย และบอกว่าใช้ข้อมูลจากบิลประเภทไหน (`ocr_source`) | `/admin/activities` |
| `ef_type`, `emission_factor` | ค่า Emission Factor (EF) แยกตามประเภท | `/admin/ef-gwp` |
| `global_warming_potential` | ค่า GWP ของก๊าซแต่ละชนิด | `/admin/ef-gwp` |
| `office_info_type` | หัวข้อข้อมูลสำนักงาน เช่น จำนวนพนักงาน, พื้นที่ (ตร.ม.), % หลอด LED | `/admin/officerec` |
| `carbon_reduction_recommendation` + `recommendation_condition` | แนวทางลดคาร์บอน, % ที่ลดได้, กิจกรรมที่ผูก และเงื่อนไขว่าจะแนะนำเมื่อไร | `/admin/officerec` |
| `tree_list` | พันธุ์ไม้ที่ใช้ในโครงการ T-VER ได้ | `/admin/tver` |
| `tver_project_detail` | ข้อมูลที่ต้องกรอกในโครงการ T-VER + เงื่อนไข (ตัวดำเนินการ + ตัวเลข เช่น พื้นที่ `<= 1000` ไร่) | `/admin/tver` |
| `project_target_rule` | เป้าหมายการจัดสรรเครดิต (% ชดเชย / % ขาย) | `/admin/allotaxdoc` |
| `project_cost_type` | รายการต้นทุนมาตรฐานของโครงการ (เช่น ค่าธรรมเนียม อบก., ค่า VVB) ราคา + VAT → ราคาสุทธิ | `/admin/allotaxdoc` |
| `documents` + Storage | เอกสาร PDF/DOCX/XLSX (ไม่เกิน 25 MB) ให้องค์กรดาวน์โหลด | `/admin/allotaxdoc` |

ค่าคงที่บางส่วนเขียนไว้ในโค้ด (ไม่ได้อยู่ในฐานข้อมูล)
- อัตราสิ้นเปลืองเชื้อเพลิงของรถแต่ละชนิด (กม./ลิตร) อ้างอิง อบก. "ข้อกำหนดในการคำนวณและรายงานคาร์บอนฟุตพริ้นท์ขององค์กร" พิมพ์ครั้งที่ 8 ก.ค. 2565 ภาคผนวก 10 ตาราง 10-1 (ใน `general_activity/calculation.ts`)
- รถ EV 6.06 กม./kWh, ราคาไฟฟ้า 4 บาท/kWh
- MAI = 9.5 kgCO2/ต้น/ปี (สูตร T-VER), อัตราภาษีเงินได้นิติบุคคล 20%

### 3.2 ข้อมูลที่องค์กรกรอก
- ข้อมูลบัญชี: อีเมล, username, ชื่อองค์กร, ประเภทธุรกิจ (`user`, `organization`)
- ข้อมูลสำนักงานของแต่ละรายการ (`org_office_info`)
- ปริมาณกิจกรรมของแต่ละรอบ (`org_activity_list` = หัวรายการ + ช่วงเวลา, `org_activity_detail` = ปริมาณแต่ละรายการย่อย + ผล tCO2e)
- กิจกรรมทั่วไป: การประชุม (`general_activity_meeting`), การเดินทาง (`general_activity_traveling`)
- โครงการ T-VER (`org_tree_project`, `org_tree_project_detail`)
- ผลการจัดสรรเครดิต (`org_credit_allocation`, `org_credit_allocation_detail`)
- ผลประเมินภาษี (`org_sell_credit` และตารางที่เกี่ยวข้อง)

### 3.3 ข้อมูลจาก OCR บิล
องค์กรแนบ **รูป** บิลค่าไฟฟ้า / บิลค่าน้ำประปา / ใบเสร็จน้ำมัน แล้วระบบอ่านค่าให้ (ดูหัวข้อ 4.3)
รูปบิลไม่ถูกเก็บลงฐานข้อมูล ใช้แค่ช่วยกรอกฟอร์ม

## 4. ฟีเจอร์ฝั่งองค์กร (ทีละหน้า)

### 4.1 สมัครสมาชิก / เข้าสู่ระบบ / ลืมรหัสผ่าน / บัญชีผู้ใช้
- **ลงทะเบียน** (`AuthModal` + `POST /api/auth/register`): กรอก username, อีเมล, รหัสผ่าน, ชื่อองค์กร → Supabase ส่ง OTP ไปที่อีเมล → ยืนยัน OTP แล้วจึงบันทึกตาราง `user` และ `organization`
  - อีเมลห้ามซ้ำ แต่ username ซ้ำได้ (ใช้แค่แสดงผล) username ยาว 3-20 ตัว ใช้ได้เฉพาะอังกฤษ/ตัวเลข/`_`/`-`
- **ล็อกอิน** (`POST /api/auth/login`): ตรวจรหัสผ่านกับ Supabase Auth → ต้องมีแถวใน `user`, `status = active`, `role` เป็น admin หรือ organization → ส่งไปหน้าตามบทบาท
- **ลืมรหัสผ่าน** (`/organization/forgot_password`): ขอลิงก์ทางอีเมล (อายุ 10 นาที) → ตั้งรหัสใหม่ ระหว่างนั้นเข้าหน้าอื่นไม่ได้
- **บัญชีผู้ใช้** (`/organization/account_user`): แก้ username / ชื่อองค์กร / ประเภทธุรกิจ, เปลี่ยนรหัสผ่าน (ต้องใส่รหัสเดิม), ลบบัญชีและข้อมูลทั้งหมดขององค์กร (`DELETE /api/account`)
- `src/proxy.ts` กันหน้าที่ต้องล็อกอิน ถ้ายังไม่ล็อกอินจะพาไปหน้า login

### 4.2 บันทึกคาร์บอนฟุตพรินต์ (3 ขั้นตอน)
เมนู `/organization/footprint` มีขั้นตอนดังนี้

**ขั้นที่ 1 ข้อมูลสำนักงาน** (`/footprint/office_info`)
- กรอกตามหัวข้อที่แอดมินตั้ง (ข้อความ / ตัวเลข / เปอร์เซ็นต์ 0-100) ไม่บังคับทุกช่อง
- ข้อมูลเป็นของ "แต่ละรายการบันทึก" ไม่ใช่ชุดเดียวทั้งองค์กร
- กด "ถัดไป" แล้วพักค่าไว้ใน sessionStorage ยังไม่บันทึกจริง

**ขั้นที่ 2 ข้อมูลกิจกรรม** (`/footprint/activity`)
- เลือกช่วงเวลา (รายเดือนหรือรายปี) และตั้งชื่อรายการ
- กรอกปริมาณของรายการย่อยแต่ละ Scope (เช่น kWh, ลิตร) หรือแนบบิลให้ OCR เติมให้
- กด "คำนวณ" → ระบบคำนวณ แล้วบันทึกทั้งข้อมูลสำนักงานและข้อมูลกิจกรรมลงฐานข้อมูล
- ถ้าช่วงเวลาซ้อนกับรายการที่มีอยู่ จะถามยืนยันก่อน

**สูตรคำนวณ (ขั้นที่ 2)** ต่อรายการย่อยหนึ่งรายการ
```
ghg_emission (tCO2e) = ปริมาณ × EF × GWP ÷ 1000
```
- ถ้าชื่อรายการมีคำว่า "น้ำประปา" ระบบถือว่าปริมาณเป็นลิตร แล้วแปลงเป็น ลบ.ม. (÷ 1000) ก่อนคำนวณ
- ถ้ารายการนั้นไม่มีค่า EF หรือ GWP ในระบบ จะใช้ 1 แทน แต่หน้าเว็บตรวจไว้ก่อนแล้วว่ารายการที่กรอกต้องมี EF
- ยอดรวม = ผลรวม ghg_emission ทุกรายการ เก็บใน `org_activity_list.total_ghg_emission`

**ขั้นที่ 3 กิจกรรมทั่วไป** (`/footprint/general_activity`) ดูหัวข้อ 4.5

### 4.3 OCR อ่านบิล (ใช้ในขั้นที่ 2)
ลำดับการทำงาน
1. ผู้ใช้แนบรูปบิล (เฉพาะรูป ไม่รับ PDF, ไม่เกิน 10 MB) ในหมวดบิลค่าไฟฟ้า / ค่าน้ำประปา / น้ำมัน
2. หน้าเว็บส่งรูปไปที่ `POST /api/ocr` (Next.js) → ส่งต่อไปที่ Python FastAPI (`scripts/api.py`) ที่ใช้ PaddleOCR อ่านข้อความ
3. `scripts/extract_bill_data.py` วิเคราะห์ข้อความที่อ่านได้
   - ระบุประเภทบิล (น้ำ / ไฟฟ้า / น้ำมัน)
   - อ่านเดือนและปีของบิล (รองรับปี พ.ศ./ค.ศ. และตัวคั่นที่ OCR อ่านผิด)
   - อ่านเลขที่บิล (มีรูปแบบเฉพาะของปั๊ม PT, Shell)
   - อ่านปริมาณ: น้ำ (ลิตร/ลบ.ม.), ไฟฟ้า (kWh), น้ำมัน (ลิตร + ชนิดน้ำมัน) ใบเสร็จน้ำมันตรวจความสมเหตุสมผลด้วย ยอดเงิน ≈ ราคาต่อลิตร × ลิตร
4. ผู้ใช้ตรวจ/แก้ค่าแต่ละบิล (`BillRow`) แล้วกด "ยืนยัน"
5. ระบบรวมยอดตามประเภทบิล แล้วเติมลงรายการย่อยที่แอดมินผูก `ocr_source` ไว้ (เช่น `electricity`, `water`, `fuel:diesel`)
6. คำนวณด้วยสูตรเดียวกับการกรอกเอง

### 4.4 รายงานและแนวทางลดคาร์บอน (`/footprint/report?id=...`)
**แสดงผล**
- ยอดรวม tCO2e ของรายการ, แยกตาม Scope 1/2/3 (ยอด + % + กราฟแท่ง)
- รายการแนวทางลดคาร์บอนที่เข้าเงื่อนไข พร้อมปริมาณที่คาดว่าลดได้
- ดาวน์โหลดรายงานเป็น PDF

**วิธีเลือกแนวทางลดคาร์บอน** (`src/lib/recommendation.ts`)
- แต่ละแนวทางที่แอดมินตั้งไว้มี: กิจกรรมที่ผูก (`scopedetail_id`), % ที่ลดได้, เงื่อนไข 0 ข้อขึ้นไป
- เงื่อนไขแต่ละข้อเทียบค่าหนึ่งกับตัวเลข ด้วย `<, <=, =, >=, >, ≠` ค่าที่ใช้เทียบเป็นได้ทั้ง
  - ปริมาณ หรือ tCO2e ของกิจกรรมที่องค์กรกรอก
  - ค่าข้อมูลสำนักงานของรายการนั้น
  - อัตราส่วน A ÷ B (เช่น kWh ÷ จำนวนพนักงาน)
- ต้องผ่าน **ทุก** เงื่อนไข ถ้าไม่มีข้อมูลจะถือว่าไม่ผ่าน (ไม่แนะนำโดยเดา)
- ปริมาณที่ลดได้ = ก๊าซของกิจกรรมที่ผูก × % ÷ 100
- เรียงจาก % มากไปน้อย ถ้ามีหลายแนวทางผูกกิจกรรมเดียวกัน แนวทางถัดไปจะคิดจากยอดที่เหลือหลังหักแนวทางก่อนหน้า (กันนับซ้ำ)

### 4.5 กิจกรรมทั่วไป: ประชุม/อบรม/อีเวนต์ และการเดินทาง (`/footprint/general_activity`)
**สิ่งที่กรอก**
- *การประชุม*: รูปแบบ ออนไลน์ หรือ ออนไซต์, อุปกรณ์ไฟฟ้าหลายชุด (ชื่อ, จำนวนเครื่อง, ชั่วโมง, กำลังไฟเป็นวัตต์) ถ้าเป็นออนไซต์ให้กรอกการเดินทางเพิ่ม (ชนิดรถ, เชื้อเพลิง, ระยะทาง, จำนวนเที่ยว)
- *การเดินทาง*: ชนิดรถ (รถยนต์ / จักรยานยนต์ / รถตู้ / รถโดยสาร / EV), เชื้อเพลิง (แก๊สโซฮอล์ E10/E20/E85, ดีเซล B7/B20, CNG, LPG, ไฟฟ้า), ระยะทาง, จำนวนเที่ยว, ถ้าเป็น EV ใส่ kWh/100 กม. ได้
- เลือกกิจกรรมเดิมจากประวัติมาแก้ไข/ลบได้

**สูตร** (`calculation.ts` ผลเป็น kgCO2e แล้วแปลงเป็น tCO2e)
```
ประชุมออนไลน์      = Σ(จำนวนเครื่อง × ชั่วโมง × kWh ต่อชั่วโมง) × EF ไฟฟ้า
เดินทางรถเชื้อเพลิง = (ระยะทาง × จำนวนเที่ยว ÷ กม.ต่อลิตร ของรถ+เชื้อเพลิงนั้น) × EF เชื้อเพลิง
เดินทางรถ EV       = ระยะทาง × จำนวนเที่ยว × kWh ต่อ กม. × EF ไฟฟ้า   (ไม่กรอกใช้ 1/6.06 kWh/กม.)
ประชุมออนไซต์      = ส่วนเดินทาง + ส่วนอุปกรณ์ไฟฟ้า
ค่าไฟโดยประมาณ     = kWh ที่ใช้ × 4 บาท
```
ค่า EF ดึงจากตาราง `emission_factor`

**ผลลัพธ์**
- ปริมาณก๊าซของการประชุม การเดินทาง และยอดรวม (tCO2e) พร้อม kWh และค่าไฟโดยประมาณ
- คำแนะนำ: ตัวเลือกที่ปล่อยก๊าซน้อยกว่าที่ใช้อยู่ (เช่น เปลี่ยนเชื้อเพลิง เปลี่ยนเป็น EV) และลดได้เท่าไร
- ดาวน์โหลด PDF (`POST .../general_activity/pdf`)
- บันทึกลง `general_activity_meeting` / `general_activity_traveling`

**ข้อจำกัด**: ข้อมูลส่วนนี้ยังไม่ผูกกับรายการบันทึก (`org_activity_list`) จึงไม่ถูกรวมในรายงานและแดชบอร์ด

### 4.6 Dashboard องค์กร (`/organization/dashboard`)
- ยอดรวมการปล่อยก๊าซ
- รายการบันทึกทั้งหมด (เรียงตามช่วงเวลา) เปิดรายงาน แก้ไข หรือลบได้
- รายการโครงการ T-VER พร้อมเครดิต แก้ไขหรือลบได้

### 4.7 จำลองโครงการปลูกป่า T-VER (`/organization/tver-simulation`)
**สิ่งที่กรอก**: ชื่อโครงการ, พันธุ์ไม้ (จาก `tree_list`), วันที่เริ่มโครงการ, ค่าตามหัวข้อที่แอดมินตั้ง (เช่น พื้นที่เป็นไร่, จำนวนต้นไม้ทั้งหมด)

**การตรวจ**: เทียบค่าที่กรอกกับเงื่อนไขของแอดมิน เช่น พื้นที่ต้อง `<= 1000` ไร่ ถ้าไม่ผ่านจะแจ้งใต้ช่อง

**สูตรคาร์บอนเครดิต** (`src/lib/tverCredits.ts`, T-VER สูตรที่ 4 การกักเก็บคาร์บอนของต้นไม้)
```
CTT(t) = T × t × MAI × 10^-3   (tCO2e สะสมถึงปีที่ t)
T   = จำนวนต้นไม้ทั้งหมดในโครงการ
t   = ปีที่ติดตามผล (คำนวณปี 1, 2, 3)
MAI = 9.5 kgCO2 ต่อต้นต่อปี
```
ตัวอย่าง: 1,000 ต้น → ปี 1 = 9.5, ปี 2 = 19, ปี 3 = 28.5 tCO2e

**ผลลัพธ์**: บันทึก `credit_year_1..3` ของโครงการ แสดงกราฟเครดิต และปุ่ม "ไปจัดสรรคาร์บอนเครดิต"

### 4.8 จัดสรรคาร์บอนเครดิต (`/organization/tver-allocation?project=...`)
- ใช้ **เครดิตปีที่ 1** ของโครงการที่เลือก
- เลือกเป้าหมาย (จาก `project_target_rule` ที่แอดมินตั้ง เช่น ชดเชย 70% / ขาย 30%)
- เลือกรายการปล่อยก๊าซขององค์กรที่จะนำเครดิตไปชดเชย

**สูตร** (ฟังก์ชันในฐานข้อมูล `save_credit_allocation` คำนวณอีกรอบตอนบันทึก)
```
โควตาชดเชย = เครดิตปี 1 × % ชดเชย
เครดิตขาย  = เครดิตปี 1 × % ขาย
นำโควตาชดเชยไปหักการปล่อยของแต่ละรายการตามลำดับ (เก่า → ใหม่) จนโควตาหมดหรือรายการหมด
```
**ผลลัพธ์**: ตารางต่อรายการว่าชดเชยได้เท่าไร เหลือการปล่อยเท่าไร และจำนวนเครดิตที่นำไปขาย ปัดทศนิยม 4 ตำแหน่ง

### 4.9 ประเมินการยกเว้นภาษีเงินได้นิติบุคคล (`/organization/tax_calculator`)
- เลือกโครงการที่จัดสรรแล้ว: เครดิตที่ขาย (CreditSold) มาจากหน้าจัดสรร ผู้ใช้ไม่ต้องกรอก
- กรอกราคาขายต่อหน่วย (บาท/tCO2e)
- ค่าใช้จ่าย: รายการมาตรฐานที่แอดมินตั้ง (ลบไม่ได้ แก้จำนวนเงินได้) + รายการที่เพิ่มเอง

**สูตร**
```
Revenue   = CreditSold × PriceCredit
Profit    = Revenue − ผลรวมค่าใช้จ่าย
TaxExempt = Profit × 20%   (ถ้า Profit ติดลบ = 0)
```
คำนวณแบบจำนวนเต็มแล้วปัดเป็นสตางค์ ให้ได้ผลตรงกับ `round(numeric, 2)` ของ PostgreSQL บันทึกด้วยฟังก์ชัน `save_tax_assessment`

**ผลลัพธ์**: รายได้, กำไร, ภาษีที่ได้รับยกเว้น (บาท)

## 6. การตรวจข้อมูลและความปลอดภัย

- **Normalize + Validate** (`src/lib/normalization.ts`, `validation.ts`): รับเลขไทย ตัด comma ห้ามติดลบ จำกัดทศนิยม ห้ามว่าง ห้ามเป็นตัวเลขล้วน จำกัดความยาว ตรวจข้อมูลซ้ำ ตรวจว่าค่าที่อ้างถึงมีอยู่จริง แสดง error ภาษาไทยใต้ช่อง
- **ตรวจ Syntax ป้องกัน SQL Injection** 3 ชั้น
  1. หน้าเว็บ (`src/lib/sqlSyntax.ts` → `containsSqlSyntax`)
  2. API ฝั่ง server (ล็อกอิน / ลงทะเบียน / บัญชี) ตรวจซ้ำ กันการยิง API ตรง
  3. ฐานข้อมูล: trigger ใน `supabase/sql_syntax_triggers.sql` ใช้กฎเดียวกัน ปฏิเสธข้อความที่คล้ายคำสั่ง SQL ในตาราง user, organization, การประชุม, การเดินทาง, เป้าหมาย, ต้นทุน, ภาษี
  - รหัสผ่านใช้โหมด lenient (อนุญาตสัญลักษณ์)
- **Row Level Security** (`supabase/rls*.sql`): แต่ละองค์กรอ่าน/เขียนได้เฉพาะข้อมูลของตัวเอง หน้า server ใช้ `org_id` จาก session จริง และตรวจว่าเป็นเจ้าของรายการก่อนเปิด
- **Foreign key** (`supabase/fk_restrict_delete.sql`): กันการลบข้อมูลอ้างอิงที่ยังถูกใช้อยู่

## 7. สรุป Input → Process → Output

| ฟีเจอร์ | Input | Process | Output |
|---|---|---|---|
| คาร์บอนฟุตพรินต์ | ข้อมูลสำนักงาน + ปริมาณกิจกรรม (กรอกเองหรือ OCR บิล) | ปริมาณ × EF × GWP ÷ 1000 | tCO2e รวม + แยก Scope, กราฟ, PDF |
| แนวทางลดคาร์บอน | ผลคาร์บอนฟุตพรินต์ + ข้อมูลสำนักงาน + เงื่อนไขแอดมิน | ตรวจเงื่อนไขทุกข้อ, ก๊าซ × % | รายการแนวทาง + tCO2e ที่ลดได้ |
| กิจกรรมทั่วไป | อุปกรณ์ไฟฟ้า, รถ, เชื้อเพลิง, ระยะทาง | สูตรไฟฟ้า/เชื้อเพลิง × EF | tCO2e, kWh, ค่าไฟ, คำแนะนำ, PDF |
| จำลอง T-VER | จำนวนต้นไม้, พื้นที่, พันธุ์ไม้, วันที่เริ่ม | ตรวจเงื่อนไข + CTT = T × t × 9.5 × 10⁻³ | เครดิตปี 1-3 (tCO2e) + กราฟ |
| จัดสรรเครดิต | เครดิตปี 1 + เป้าหมาย % + รายการปล่อยก๊าซ | แบ่งชดเชย/ขาย, หักตามลำดับ | ยอดชดเชยต่อรายการ, เครดิตที่ขาย |
| ประเมินภาษี | เครดิตขาย, ราคาขาย, ค่าใช้จ่าย | (เครดิต × ราคา − ค่าใช้จ่าย) × 20% | รายได้, กำไร, ภาษีที่ยกเว้น (บาท) |

## 8. ข้อจำกัดและสิ่งที่ยังไม่สมบูรณ์

- Dashboard ของแอดมินยังเป็นข้อมูลตัวอย่าง
- กิจกรรมทั่วไป (ประชุม/เดินทาง) ยังไม่ถูกรวมในรายงานและแดชบอร์ดขององค์กร
- การจัดสรรเครดิตและการประเมินภาษีใช้เฉพาะ **เครดิตปีที่ 1**
- แนวทางลดคาร์บอนทุกแนวทางคิดแบบ "% ของก๊าซกิจกรรมที่ผูก" ยังไม่มีสูตรเฉพาะมาตรการ (โค้ดเตรียมจุดต่อยอดไว้แล้ว)
- ค่ารถตู้/รถโดยสารที่ใช้ CNG หรือ LPG ไม่มีในตารางอ้างอิงแยกตามชนิดรถ จึงใช้ค่ารถ NGV / LPG ทั่วไปแทน
- OCR รับเฉพาะรูป ไม่รับ PDF และต้องเปิดเซิร์ฟเวอร์ Python แยก
- ฟังก์ชันฐานข้อมูล `save_credit_allocation` และ `save_tax_assessment` อยู่ใน Supabase ไม่มีไฟล์ SQL ใน repo
- สคริปต์ใน `supabase/` ต้องรันเองใน SQL Editor (เช่น trigger ตรวจ SQL, RLS) ถ้าไม่รันบางฟีเจอร์จะไม่ทำงานหรือไม่ปลอดภัย
